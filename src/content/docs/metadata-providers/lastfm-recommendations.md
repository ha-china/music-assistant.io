# LastFM 元数据提供商 <img src="/assets/icons/audioscrobbler-icon.svg" alt="Preview image" style="width: 126px; float: right;"  loading="lazy" />

Music Assistant 能够基于 Last.fm 提供的可用数据生成推荐行。由 <a href="https://github.com/OzGav" target="_blank" rel="noopener noreferrer">Gavin</a> 贡献并维护

> [!NOTE]
> 此提供商要求同时安装流媒体提供商（streaming providers），以便将推荐内容链接到可播放的源

## 功能

该提供商最多可创建九个推荐行，通过四个可独立启用的开关进行分组（每行仍可通过“发现”视图的编辑模式显示或隐藏）：

- 个性化（2 行）：发现相似艺人 + 发现相似曲目，以您在 Music Assistant 中播放次数最多的艺人和曲目为种子
- 全球榜单（2 行）：来自 Last.fm 全球榜单的全球热门艺人 + 全球热门曲目
- 流派（3 行）：您最常播放的 Last.fm 流派的热门艺人 / 专辑 / 曲目，每天轮换您排名前三的流派中的一个（需要 Last.fm 用户名）
- 地理（2 行）：您从列表中选择的国家的热门艺人 + 热门曲目

这些行会展示您当前没有的音乐，并且每个项目都会解析到您已配置的流媒体提供商（例如 Spotify），因此只需点击一下即可播放。

此提供商还支持在整个 UI 中填充“相似艺人”、“相似曲目”和“艺人热门曲目”。

## 配置

MA 内置了 API 密钥，但如果希望使用个人 API 密钥，请按照<a href="https://www.last.fm/api/authentication" target="_blank" rel="noopener noreferrer">此处</a>的前两个步骤获取。它可以在开启高级开关后看到的字段中输入。

- **Last.fm 用户名**（可选）：仅流派行需要
- **Last.fm API 密钥**（可选，高级）：如果您愿意，可以使用自己的密钥覆盖内置密钥
- 根据需要启用行类别。有关将为每个选择提供的行的描述，请参见上文

### 设置

- <b>刷新推荐。</b>此按钮（需要选择高级设置）将清除推荐行并立即触发刷新

### 每行的构建方式

每行最多包含 10 个项目。它们的构建方式如下：

**个性化（相似艺人 / 相似曲目）**
“相似艺人”以最多五名艺人为种子，“相似曲目”以最多二十首曲目为种子，按它们在您近期收听中出现的频率排名。系统会向 Last.fm 请求每个种子的相似项目；合并后的列表会进行去重，并按 Last.fm 的相似度匹配分数排序，得分最高的项目会针对可用的流媒体提供商进行解析。在给定收听历史的情况下，该行是完全确定性的。使用相同播放历史进行两次刷新会产生相同的行。只有当收听习惯改变或 Last.fm 更新其相似度数据时，它才会发生变化。

**全球榜单（热门艺人 / 热门曲目）**
按顺序获取 Last.fm 的全球榜单，解析前 15 名，并显示在可用流媒体提供商中匹配到内容的前 10 名。无随机化。顺序完全按照 Last.fm 的榜单排名。当 Last.fm 的榜单发生变化时，该行也会随之改变。

**流派（热门艺人 / 专辑 / 曲目）**
在您排名前三的 Last.fm 流派中循环，每天一个不同的流派。对于当天的流派，它会获取 Last.fm 的前 60 名，剔除已在您媒体库中的内容，然后通过“前 3 名 + 随机 7 名”的方式选择项目：前三名固定为 Last.fm 的前三名，另外七名是从其余部分中随机抽取的样本。每次更新任务运行时，随机部分都会轮换，而前三名保持不变。

**地理（热门艺人 / 热门曲目）**
与全球榜单相同，但使用 Last.fm 的各国榜单。按榜单顺序取前 15 名，解析前 10 名。无随机化。

## 已知问题 / 注意事项

  - 个性化行需要 Music Assistant 中的收听历史，因此全新安装且没有播放记录的情况下不会生成这些行
  - 流派行需要您的 Last.fm 用户名。如果没有，流派开关将不起作用
  - 必须配置至少一个公开媒体库/搜索功能的流媒体提供商（例如 Spotify、Tidal、Apple Music），否则没有可供解析项目的目标，行将为空
  - 冷门的艺人/曲目可能在您的流媒体提供商中找不到，并且会从该行中静默移除。如果某行看起来很短，通常就是这个原因
  - 清除缓存并立即重建通常会产生非常相似的结果——这并不是因为提供了缓存数据，而是因为 Last.fm 自身对“与 X 相似”的响应是稳定的

### 选择刷新间隔

默认的 6 小时是一个合理的折中方案。合适的值取决于您的需求：

短间隔（1-3 小时）：
- 个性化行对近期收听的响应更快——您今天早上播放的曲目到下午就能影响“相似艺人”。
- 全球和地理行能更快地反映 Last.fm 的榜单变动。
- 缺点：行会在您浏览时发生变化。如果一首曲目吸引了您的眼球但您没有播放它，下次它可能就不见了。如果您喜欢按自己的节奏浏览一行，短间隔将不太理想。

长间隔（12-24 小时）：
- 行保持稳定的时间足够长，让您能够实际听完所有内容。
- API 调用次数更少。
- 潜在缺点：个性化和全球行可能会显得过时，尤其是如果您的近期收听习惯发生了改变。
