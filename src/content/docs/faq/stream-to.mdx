# 我想串流到的设备

Music Assistant 通过播放器提供程序（player provider）向设备播放音频，每种类型的设备或协议都有对应的提供程序。从你想要用来播放的设备类型入手，选择驱动它的提供程序。

<TilePage page={PLAYERS_PAGE} />

## 并排比较各播放器

下表总结了每个播放器提供程序能够实现的功能。绿色对勾表示支持该功能。请注意，DLNA 和 Home Assistant 播放器可能会因相关标准实现不佳而受到影响。如果其中一种播放器工作不正常，而你的设备支持其他协议，请改用其他协议。

<PlayerCapabilities />

如果设备支持多种协议，它们会被合并为一个播放器，并在设置中显示为播放器名称附近的标签（chip）。在[单个播放器设置](/settings/individual-player/#output-protocols)中，你可以设置默认协议，或禁用任何不使用的协议。

## 规划特定的配置

本页的其余内容涵盖了需要比单纯选择提供程序更多操作的情况，例如你已有的设备、手机、浏览器，或者你尚未购买的东西。

## 我的本地 HA 或 MA 设备

原生解决方案是 [Local Audio 应用](/player-support/local-audio/)，它可以把运行它的那台机器变成 Sendspin 播放器。

另外，对于 HA，你可以安装 <a href="https://github.com/pssc/ha-addon-squeezelite" target="_blank" rel="noopener noreferrer">squeezelite 应用</a>，这样就可以通过音频连接从 HA 主机串流到你的扬声器或功放。

## 我的任意联网设备

### 串流到 Squeezelite 兼容客户端

在你的手机或其他设备上安装任意<a href="https://sourceforge.net/projects/lmsclients/files/squeezelite/" target="_blank" rel="noopener noreferrer">Squeezelite 兼容应用程序</a>（即<a href="https://en.wikipedia.org/wiki/Squeezelite" target="_blank" rel="noopener noreferrer">Squeezelite 软件客户端</a>，有时也被称为“Squeeze Lite”应用），然后 MA 应该就能够向它串流。

如果你的本地网络中有 Squeezelite 兼容客户端，MA 将能够自动检测并向它们串流（这通过 Squeezelite 兼容性实现，你无需为其添加任何特定的配置或凭据）。请注意，Squeezelite 客户端通常没有自己的用户界面，因此必须通过 Music Assistant 进行控制。

有关<a href="https://github.com/orgs/music-assistant/discussions/1123#discussioncomment-6652948" target="_blank" rel="noopener noreferrer">如何在 Windows 上运行 squeezelite</a> 的示例，请参见此处

[Music Assistant 伴侣应用](/companion-app/)也可以配置为运行 squeezelite 客户端，从而可以在运行该应用的设备上播放。

## 我的基于 ESP32 的设备

MA 的原生解决方案是使用 [Sendspin](https://www.sendspin-audio.com/)。该设备需要至少 2MB 的 PSRAM 和 4MB 的闪存。使用 [ESPHome](https://esphome.io/components/media_source/sendspin/) 对设备进行刷写。许多更接近成品的产品在 [RealDeco 的 GitHub 仓库](https://github.com/RealDeco/sendspin-guition) 中提供了现成的软件

如果硬件具有至少 4MB 的闪存和 4MB 的 PSRAM，它就能够直接运行 squeezelite。使用 <a href="https://github.com/sle118/squeezelite-esp32" target="_blank" rel="noopener noreferrer">Squeezelite ESP32 固件</a>。一个带有扬声器接线端子的不错成品方案是 <a href="https://www.tindie.com/products/sonocotta/louder-esp32/" target="_blank" rel="noopener noreferrer">Louder ESP32</a>

如果 ESP32 设备上运行的其他固件已被 Home Assistant 发现，请使用 <a href="https://music-assistant.io/integration/installation/" target="_blank" rel="noopener noreferrer">Home Assistant 播放器提供程序</a>将 HA 媒体播放器实体（entity）暴露给 MA。如果暴露的播放器运行的是 ESPHome，请考虑在播放器设置中将输出编解码器（Output Codec）更改为 `MP3 (lossy)`（如果它还不是默认值），因为这可能已是该播放器能够处理的极限。

还有一个<a href="https://github.com/jorgenkraghjakobsen/snapclient" target="_blank" rel="noopener noreferrer">Snapclient 移植版本</a>也可以使用。

## 我的蓝牙扬声器

向蓝牙扬声器和耳机播放有两种方式：Sendspin 蓝牙桥接器（Sendspin Bluetooth Bridge），或在备用的 Raspberry Pi 上运行 piCorePlayer。

### Sendspin Bluetooth Bridge

<a href="https://github.com/trudenboy/sendspin-bt-bridge" target="_blank" rel="noopener noreferrer">Sendspin 蓝牙桥接器</a>是最直接的途径。它可以运行在任何带有蓝牙适配器（内置或 USB 适配器）的 Linux 机器上，你与之配对的每个扬声器或每副耳机都会作为 [Sendspin](/player-support/sendspin/) 播放器出现在 Music Assistant 中。它可以同时容纳多台设备，并且可以像任何其他 Sendspin 播放器一样进行分组并一起播放。它可以作为 Home Assistant 应用安装，也可以在 Docker 或 LXC 容器中运行，并且已经在 Home Assistant OS、Ubuntu、Proxmox、OpenWrt 以及 Raspberry Pi 4 和 5 上进行了测试。它是一个社区项目，而非 Music Assistant 的一部分，因此如有任何需要帮助的问题，请在其自己的仓库中提出。

### piCorePlayer

如果你有一个备用的 Raspberry Pi（任何型号），<a href="https://www.picoreplayer.org" target="_blank" rel="noopener noreferrer">piCorePlayer</a> 也可以连接蓝牙扬声器。为了获得最佳效果：

* 使用有线以太网连接而不是 Wi-Fi。在大多数 Raspberry Pi 型号上，蓝牙和 Wi-Fi 共享同一个芯片和天线，同时使用两者通常会导致断连和更短的覆盖范围。

* Raspberry Pi 内置的蓝牙或普通的 USB 适配器也可以工作，但有局限性。Raspberry Pi 必须自己编码音频，这可能会将你限制在较低质量的编解码器上，例如 <a href="https://en.wikipedia.org/wiki/SBC_(codec)" target="_blank" rel="noopener noreferrer">SBC</a> 或标准 <a href="https://en.wikipedia.org/wiki/AptX" target="_blank" rel="noopener noreferrer">aptX</a>。较旧的 Raspberry Pi 可能会引入额外的延迟，而且内置天线较弱，尤其是在金属或厚塑料外壳中。

* 为了获得最佳音质，请使用专用的蓝牙音频发射器，例如 <a href="https://global.sennheiser-hearing.com/products/btd-700" target="_blank" rel="noopener noreferrer">Sennheiser BTD 700</a> 或 <a href="https://uk.creative.com/p/speakers/creative-bt-w6" target="_blank" rel="noopener noreferrer">Creative BT-W6</a>。它们作为 USB 声卡插入并自行处理编码，包括 <a href="https://www.aptx.com/aptx-adaptive" target="_blank" rel="noopener noreferrer">aptX Adaptive</a> 和 aptX HD 等高质量编解码器。这样即使是 Raspberry Pi 1 也能驱动现代耳机，连接更稳定，并且带有物理配对按钮。

如果你使用 USB 发射器，请在 piCorePlayer 的 `Squeezelite Settings` 页面上更改两个设置。将 `Audio Output` 设置为 `USB Audio` 并保存。每次重启后，返回该页面，点击 `Card Control`，然后取消勾选 `Raspberry Pi Built-in Audio` 部分中的复选框，以关闭内置音频。

### 解决蓝牙延迟问题

蓝牙本身会带来延迟，因此蓝牙扬声器的声音可能会比你的其他扬声器晚一点听到。如果播放器提供**静态播放延迟（Static playback delay (ms)）**设置，你可以使用它让音频重新同步。它校正的是固定的延迟，而不是漂移的延迟，因此可能无法完全解决问题。

## Music Assistant

<img src="/assets/label-easiest-noshadow.png" alt="easiest label" style="width: 64px;"  loading="lazy" />

To bring a turntable, microphone or other line-in into Music Assistant, the native solution is [Sendspin Source](/plugins/sendspin-source/). Once a Sendspin device with an audio input is set up in Music Assistant, its input appears as a Live Input you can play on any player, stereo pair or group. If the device can tell when a signal is present, it can start playing automatically, for example when you lower the needle on a record.

The first off-the-shelf device built for this is [Apollo Automation's CAST PRO-1](https://apolloautomation.com/products/cast-pro-1). It needs firmware 26.11.3.2 or newer (3.3 recommended) and Music Assistant 2.10.7 or newer. Before buying, note that:

- The input expects line level, so a turntable without a built-in phono preamp needs an external one
- While the line-in is streaming, the CAST PRO-1's own output is optical only, even if set to analog

The second off-the-shelf device is the Nabu Casa [Connect AUX-2](https://www.home-assistant.io/connect/aux-2/). It is output only so cannot be used for line-in.

<img src="/assets/label-intermediate-noshadow.png" alt="intermediate label" style="width: 64px;"  loading="lazy" />
Another way is you could use <a href="http://www.darkice.org/" target="_blank" rel="noopener noreferrer">DarkIce</a> to capture and <a href="https://www.icecast.org/" target="_blank" rel="noopener noreferrer">Icecast</a> to build a solution that will digitize and stream audio from your analog audio equipment like a vinyl record player (turntable/phonograph/gramophone) as a web radio stream (URL) that you could add as a radio station in Music Assistant.

对于这样的项目，你需要一个既能提供音频输入又能进行数字化的音频采集和 ADC（模数转换器）设备。例如，你可以使用来自 <a href="https://www.behringer.com/en/products?category_id=audio-interfaces--usb-audio-interfaces" target="_blank" rel="noopener noreferrer">Behringer</a> 或 <a href="https://www.ikmultimedia.com/products/irigstream/" target="_blank" rel="noopener noreferrer">IK Multimedia</a> 的 USB 音频设备接口适配器，或者带有 ADC 的 <a href="https://www.hifiberry.com/blog/need-some-input/" target="_blank" rel="noopener noreferrer">HiFiBerry 板卡</a>。

你可以<a href="https://maker.pro/raspberry-pi/projects/how-to-build-an-internet-radio-station-with-raspberry-pi-darkice-and-icecast" target="_blank" rel="noopener noreferrer">在此处</a>找到一份通用教程，喜欢分步指南的读者可以查看<a href="https://github.com/quebulm/Raspberry-Pi-Vinyl-Streamer" target="_blank" rel="noopener noreferrer">这里</a>和<a href="https://github.com/gieljnssns/darkice-libaacplus-rpi-guide/blob/master/README.md" target="_blank" rel="noopener noreferrer">这里</a>（其中第一个还提供了适用于 Raspberry Pi 3 / Raspberry Pi Zero 2 W 的预配置 Linux 设备镜像）。 



## Web Radio

你可以间接串流到只接受 URL 的设备，例如网络电台。为此，你需要运行 Home Assistant 并执行以下操作：

- 安装 https://github.com/Poeschl-HomeAssistant-Addons/mpd（这会创建一个 mpd media_player 实体）
- 在 mpd 应用中启用 httpd_output（它允许通过网络进行串流）
- 在 Music Assistant 中使用 HA 媒体播放器插件，并选择 mpd 作为输出

感谢 <a href="https://github.com/mrueg" target="_blank" rel="noopener noreferrer">Manuel Rüger</a>，他在<a href="https://github.com/orgs/music-assistant/discussions/2410#discussioncomment-10885780" target="_blank" rel="noopener noreferrer">这里</a>向我们展示了这一方法

## 我尚未购买的设备！

Music Assistant 中可用的播放器提供程序的功能摘要[可在此处查看](/player-support/)。

一般来说，以下协议/设备应能让你几乎没有设置上的困难：

-	任何支持 <a href="https://en.wikipedia.org/wiki/AirPlay" target="_blank" rel="noopener noreferrer">AirPlay</a> 的设备/扬声器
-	任何支持 <a href="https://en.wikipedia.org/wiki/Google_Cast" target="_blank" rel="noopener noreferrer">Google Cast 协议</a>的设备/扬声器（也称为内置 cast）
-	<a href="https://en.wikipedia.org/wiki/Squeezebox_(network_music_player)" target="_blank" rel="noopener noreferrer">Squeezebox 硬件</a>
-	基于 <a href="https://sourceforge.net/projects/lmsclients/files/squeezelite/" target="_blank" rel="noopener noreferrer">Squeezelite</a> 的播放器
-	<a href="https://www.sonos.com/en-us/home" target="_blank" rel="noopener noreferrer">Sonos</a>

我们认为大多数人听不出高于 CD 音质的采样率差异，因此强烈推荐 AirPlay。它具有良好的同步协议，并在消费类设备中得到了广泛实现。Music Assistant 还有一个用于 AirPlay 的 Sendspin 桥接器，这意味着 AirPlay 设备可以与其他 Sendspin 设备同步播放。此外，许多 Sonos 设备也可以与 AirPlay 设备同步，这是另一个加分项。

对大多数人来说，应该考虑自己已有的设备并与之适配（如果是 DLNA，则鉴于某些设备的怪癖，可以考虑更换），同时还要考虑自己的预算。

最后，如果你计划对播放器进行分组并希望使用 DSP 设置，请在[数字信号处理（DSP）概述](/dsp/)中查看在这种情况下哪些协议支持 DSP
