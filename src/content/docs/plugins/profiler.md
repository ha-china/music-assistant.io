# Profiler <img src="/assets/icons/profiler-icon.svg" alt="Preview image" style="width: 70px; float: right;"  loading="lazy" />

Profiler 插件会记录 Music Assistant 服务器实际正在执行的操作——处理器使用率、内存占用以及服务器内部的延迟——并将其转换成一份可以附加到错误报告中的单一报告。它用于诊断各种性能问题，例如 CPU 使用率过高、内存持续增长或音频断续，并且这一切都可以在 Music Assistant 界面中完成，无需通过 shell 访问运行服务器的机器。

> [!WARNING]
> 此插件仅供临时安装，通常是因为维护者在支持请求中要求你这样做。拿到报告后请将其卸载——它并非为日常使用而设计。自 Music Assistant 2.10 起可用。

## 功能特性

- 飞行记录器每 10 秒对服务器健康状况进行一次采样，并保留 24 小时的历史记录，因此报告可以说明数小时前发生的情况
- 监控服务器内部的延迟，这通常是音频断续和界面迟缓的原因
- 按固定间隔自动捕获处理器分析（profile），也可以在重现问题时使用 **Profile now**（立即分析）按钮按需捕获
- 可选的内存分配跟踪功能，用于排查内存泄漏
- 生成一份自包含的报告，可以是 JSON 格式，也可以是可直接粘贴到 issue 中的 markdown 格式
- 报告仅包含代码位置、计数器和测量数据——不包含媒体标题、文件路径、URL 或账户名称——因此可以放心公开发布

## 创建报告

1. 通过**设置 → 插件 → 添加插件**添加该插件。测量会立即开始。
2. 重现该问题；如果问题是随机出现的，也可以让插件保持运行。如果你可以按需重现问题，请在重现之前在插件设置中按下 **Profile now**（立即分析），让一个 CPU 分析窗口覆盖这一时间段。
3. 使用 `profiler/report` API 命令生成报告。传入 `markdown=true` 即可获得可直接粘贴到 issue 中的版本。
4. 将报告附到你的 GitHub issue 或支持请求中。
5. 卸载该插件。

每份报告还会以 `report.json` 和 `report.md` 的形式写入服务器数据目录内的 `profiler` 文件夹，因此你也可以改为从那里获取报告。

## 设置

该插件为单实例，开箱即用；默认设置适用于大多数情况。

- <b>定期 CPU 分析。</b>按固定间隔自动捕获一个 CPU 分析窗口。默认开启。在捕获窗口期间，服务器的运行速度会略微变慢
- <b>CPU 分析窗口时长（秒）。</b>每个窗口在处理其结果之前记录数据的时长
- <b>CPU 分析间隔（分钟）。</b>自动捕获新窗口的频率
- <b>跟踪内存分配（tracemalloc）。</b>跟踪内存的分配位置，使报告能够显示分配最多的代码位置，以及它们在两份报告之间的增长情况。默认关闭，因为它会使内存跟踪的开销大约翻倍，并在启用期间拖慢服务器，因此仅在排查内存泄漏时才开启
- <b>Profile now（立即分析）。</b>按需捕获一个分析窗口，例如在你重现某个问题时。结果会出现在下一份报告中

在不捕获分析时，该插件的开销可以忽略不计。

> [!WARNING]
> `profiler/report` 命令接受一个 `include_object_census=true` 选项，它会额外统计服务器在内存中持有的一切对象。在媒体库较大时，它可能使服务器卡死数秒，因此仅在被要求时才使用。
