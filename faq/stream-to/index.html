Section titled “我想串流到的设备”

并排比较各播放器

Section titled “并排比较各播放器”

下表总结了每个播放器提供程序能够实现的功能。绿色对勾表示支持该功能。请注意，DLNA 和 Home Assistant 播放器可能会因相关标准实现不佳而受到影响。如果其中一种播放器工作不正常，而你的设备支持其他协议，请改用其他协议。

各列含义
Hi Res
能承载高于 48kHz 或 16bit 的音频。
无损
能以无损压缩方式承载音频。
完美同步
此类播放器分组后可以彼此保持时间同步。
同步微调
可为单个播放器设置延迟，把跑前或跑后的播放器拉回与分组同步。
交叉淡入淡出
一首歌可以平滑过渡到下一首。
立体声配对
两台播放器可配对为一个设备的左右声道。
设备按键
设备自带的按键可以控制 Music Assistant 播放。
设备语音
设备内置的语音助手可以控制播放。
播放器选项
该提供方暴露设备专属设置，比如播放器自己的低音和高音。

如果设备支持多种协议，它们会被合并为一个播放器，并在设置中显示为播放器名称附近的标签（chip）。在单个播放器设置中，你可以设置默认协议，或禁用任何不使用的协议。

我的本地 HA 或 MA 设备

Section titled “我的本地 HA 或 MA 设备”

原生解决方案是 Local Audio 应用，它可以把运行它的那台机器变成 Sendspin 播放器。

另外，对于 HA，你可以安装 squeezelite 应用，这样就可以通过音频连接从 HA 主机串流到你的扬声器或功放。

此选项的故障排除步骤

下面列出的一些问题可能会影响此解决方案，而以下设置应能避免所有这些问题：

  • 在 SqueezeLite 应用中启用“Show unused configuration options”（显示未使用的配置选项），然后设置：
    • build：pa（PortAudio）或 alsa
    • options：-a 150ms（目标延迟，可试验找出最佳值）
  • 确保在 Music Assistant 中该播放器的高级设置（Advanced Settings）里，输出格式（Output format）被设置为除 WAV 以外的任何格式。

切换曲目时音频过快或过慢（采样率错误）

Section titled “切换曲目时音频过快或过慢（采样率错误）”

SqueezeLite 的 PulseAudio 版本存在一个已知问题：切换曲目时会以错误的采样率播放音频。

如果遇到此问题，请在 SqueezeLite 设置中启用“Show unused configuration options”，并将 build 类型更改为 pa（PortAudio）或 alsa。

切换曲目时开头音频被吞或出现卡顿

Section titled “切换曲目时开头音频被吞或出现卡顿”

SqueezeLite 的 PulseAudio 版本还存在已知的切换曲目时的同步问题。

如果遇到此问题，请按照上述方法将 build 类型更改为 pa（PortAudio）或 alsa。

“直升机噪音” / 播放被切断

Section titled ““直升机噪音” / 播放被切断”

如果听到“直升机噪音”，请将目标延迟调高。

为此，请启用“Show unused configuration options”，并在使用 ALSA 或 PA（PortAudio）build 时，在 options 文本框中添加 -a 150ms。可能需要尝试更高或更低的值。

我的任意联网设备

Section titled “我的任意联网设备”

串流到 Squeezelite 兼容客户端

Section titled “串流到 Squeezelite 兼容客户端”

在你的手机或其他设备上安装任意Squeezelite 兼容应用程序（即Squeezelite 软件客户端，有时也被称为“Squeeze Lite”应用），然后 MA 应该就能够向它串流。

如果你的本地网络中有 Squeezelite 兼容客户端，MA 将能够自动检测并向它们串流（这通过 Squeezelite 兼容性实现，你无需为其添加任何特定的配置或凭据）。请注意，Squeezelite 客户端通常没有自己的用户界面，因此必须通过 Music Assistant 进行控制。

有关如何在 Windows 上运行 squeezelite 的示例，请参见此处

Music Assistant 伴侣应用也可以配置为运行 squeezelite 客户端，从而可以在运行该应用的设备上播放。

我的基于 ESP32 的设备

Section titled “我的基于 ESP32 的设备”

MA 的原生解决方案是使用 Sendspin。该设备需要至少 2MB 的 PSRAM 和 4MB 的闪存。使用 ESPHome 对设备进行刷写。许多更接近成品的产品在 RealDeco 的 GitHub 仓库 中提供了现成的软件

如果硬件具有至少 4MB 的闪存和 4MB 的 PSRAM，它就能够直接运行 squeezelite。使用 Squeezelite ESP32 固件。一个带有扬声器接线端子的不错成品方案是 Louder ESP32

如果 ESP32 设备上运行的其他固件已被 Home Assistant 发现，请使用 Home Assistant 播放器提供程序将 HA 媒体播放器实体（entity）暴露给 MA。如果暴露的播放器运行的是 ESPHome，请考虑在播放器设置中将输出编解码器（Output Codec）更改为 MP3 (lossy)（如果它还不是默认值），因为这可能已是该播放器能够处理的极限。

还有一个Snapclient 移植版本也可以使用。

我的蓝牙扬声器

Section titled “我的蓝牙扬声器”

向蓝牙扬声器和耳机播放有两种方式：Sendspin 蓝牙桥接器（Sendspin Bluetooth Bridge），或在备用的 Raspberry Pi 上运行 piCorePlayer。

Sendspin Bluetooth Bridge

Section titled “Sendspin Bluetooth Bridge”

Sendspin 蓝牙桥接器是最直接的途径。它可以运行在任何带有蓝牙适配器（内置或 USB 适配器）的 Linux 机器上，你与之配对的每个扬声器或每副耳机都会作为 Sendspin 播放器出现在 Music Assistant 中。它可以同时容纳多台设备，并且可以像任何其他 Sendspin 播放器一样进行分组并一起播放。它可以作为 Home Assistant 应用安装，也可以在 Docker 或 LXC 容器中运行，并且已经在 Home Assistant OS、Ubuntu、Proxmox、OpenWrt 以及 Raspberry Pi 4 和 5 上进行了测试。它是一个社区项目，而非 Music Assistant 的一部分，因此如有任何需要帮助的问题，请在其自己的仓库中提出。

piCorePlayer

Section titled “piCorePlayer”

如果你有一个备用的 Raspberry Pi（任何型号），piCorePlayer 也可以连接蓝牙扬声器。为了获得最佳效果：

  • 使用有线以太网连接而不是 Wi-Fi。在大多数 Raspberry Pi 型号上，蓝牙和 Wi-Fi 共享同一个芯片和天线，同时使用两者通常会导致断连和更短的覆盖范围。

  • Raspberry Pi 内置的蓝牙或普通的 USB 适配器也可以工作，但有局限性。Raspberry Pi 必须自己编码音频，这可能会将你限制在较低质量的编解码器上，例如 SBC 或标准 aptX。较旧的 Raspberry Pi 可能会引入额外的延迟，而且内置天线较弱，尤其是在金属或厚塑料外壳中。

  • 为了获得最佳音质，请使用专用的蓝牙音频发射器，例如 Sennheiser BTD 700 或 Creative BT-W6。它们作为 USB 声卡插入并自行处理编码，包括 aptX Adaptive 和 aptX HD 等高质量编解码器。这样即使是 Raspberry Pi 1 也能驱动现代耳机，连接更稳定，并且带有物理配对按钮。

如果你使用 USB 发射器，请在 piCorePlayer 的 Squeezelite Settings 页面上更改两个设置。将 Audio Output 设置为 USB Audio 并保存。每次重启后，返回该页面，点击 Card Control，然后取消勾选 Raspberry Pi Built-in Audio 部分中的复选框，以关闭内置音频。

解决蓝牙延迟问题

Section titled “解决蓝牙延迟问题”

蓝牙本身会带来延迟，因此蓝牙扬声器的声音可能会比你的其他扬声器晚一点听到。如果播放器提供**静态播放延迟（Static playback delay (ms)）**设置，你可以使用它让音频重新同步。它校正的是固定的延迟，而不是漂移的延迟，因此可能无法完全解决问题。

我的 iPhone

Section titled “我的 iPhone”

Music Assistant

Section titled “Music Assistant”

要将唱盘、麦克风或其他线路输入引入 Music Assistant，原生解决方案是 Sendspin Source。一旦在 Music Assistant 中设置了带有音频输入的 Sendspin 设备，其输入就会显示为实时输入（Live Input），你可以在任何播放器、立体声对或分组上播放。如果设备能够检测到信号存在，它可以自动开始播放，例如当您将唱针放到唱片上时。

第一款为此设计的现成设备是 Apollo Automation 的 CAST PRO-1。它需要固件 26.11.3.2 或更新版本（推荐 3.3）以及 Music Assistant 2.10.7 或更新版本。购买前请注意：

  • 输入需要线路电平，因此没有内置唱机前置放大器的唱盘需要外接一个
  • 在线路输入串流期间，CAST PRO-1 自身的输出仅为光纤输出，即使设置为模拟输出也是如此

第二款现成设备是 Nabu Casa Connect AUX-2。它仅支持输出，因此不能用于线路输入。

另一种方法是使用 DarkIce 进行采集，并使用 Icecast 构建一个解决方案，将来自模拟音频设备（如黑胶唱片机（唱盘/留声机/电唱机））的音频数字化并作为网络电台流（URL）进行串流，你可以将其作为电台添加到 Music Assistant 中。

对于这样的项目，你需要一个既能提供音频输入又能进行数字化的音频采集和 ADC（模数转换器）设备。例如，你可以使用来自 Behringer 或 IK Multimedia 的 USB 音频设备接口适配器，或者带有 ADC 的 HiFiBerry 板卡。

你可以在此处找到一份通用教程，喜欢分步指南的读者可以查看这里和这里（其中第一个还提供了适用于 Raspberry Pi 3 / Raspberry Pi Zero 2 W 的预配置 Linux 设备镜像）。

Web Radio

Section titled “Web Radio”

你可以间接串流到只接受 URL 的设备，例如网络电台。为此，你需要运行 Home Assistant 并执行以下操作：

  • 安装 https://github.com/Poeschl-HomeAssistant-Addons/mpd（这会创建一个 mpd media_player 实体）
  • 在 mpd 应用中启用 httpd_output（它允许通过网络进行串流）
  • 在 Music Assistant 中使用 HA 媒体播放器插件，并选择 mpd 作为输出

感谢 Manuel Rüger，他在这里向我们展示了这一方法

我尚未购买的设备！

Section titled “我尚未购买的设备！”

Music Assistant 中可用的播放器提供程序的功能摘要可在此处查看。

一般来说，以下协议/设备应能让你几乎没有设置上的困难：

  • 任何支持 AirPlay 的设备/扬声器
  • 任何支持 Google Cast 协议的设备/扬声器（也称为内置 cast）
  • Squeezebox 硬件
  • 基于 Squeezelite 的播放器
  • Sonos

我们认为大多数人听不出高于 CD 音质的采样率差异，因此强烈推荐 AirPlay。它具有良好的同步协议，并在消费类设备中得到了广泛实现。Music Assistant 还有一个用于 AirPlay 的 Sendspin 桥接器，这意味着 AirPlay 设备可以与其他 Sendspin 设备同步播放。此外，许多 Sonos 设备也可以与 AirPlay 设备同步，这是另一个加分项。

对大多数人来说，应该考虑自己已有的设备并与之适配（如果是 DLNA，则鉴于某些设备的怪癖，可以考虑更换），同时还要考虑自己的预算。

最后，如果你计划对播放器进行分组并希望使用 DSP 设置，请在数字信号处理（DSP）概述中查看在这种情况下哪些协议支持 DSP
